# 指標の定義

計算は observatory/metrics.py。時刻はすべて日本時間。

## 観測の回（run）

近い時刻の観測を1回にまとめる。観測時刻を並べて、45分（config/project.json の run_gap_minutes）より空いたところで区切る。回の時刻は、その回の最初の観測時刻。定時観測とタグ探しは別に数える。

## 人気の古さ（日）

その回の人気の上位20本について「回の時刻 − 公開時刻」を日で出し、中央値をとる。それを回ごとに出して、回をまたいだ中央値をとる。

## 人気のスキ

その回の人気の上位20本のスキの中央値。回をまたいだ中央値。

## 新着40本目の古さ（時間）と、1日の新着（目安）

その回の新着で、40本目（40本に満たなければ最後）の記事が何時間前の公開か。1日の新着（目安）は「本数 ÷ その時間 × 24」。回をまたいだ中央値。

注意：タグ探しの回は、ハッシュタグのページから新着に切り替えて数えている。定時観測は ?mode=new のページを直接見ている。測り方が違うので、同じ出どころの中だけで比べる（例：#AI活用 は定時観測で160本台、タグ探しで約76本と出る）。

## 1日の新着（重なりなし）

新着で見かけた記事のうち、公開が決めた24時間に入る本数（同じ記事は1本）。新着が深く（何時間分も）見えていて、観測の間が短いときだけ正しい。#AI活用 のように新着が速いタグでは、観測の間が空くと少なめに出る。

## 新着から人気に入った割合

新着で見かけた記事のうち、公開が決めた期間に入るものを対象にする。そのうち、どこかの回で人気に出た割合。ダッシュボードでは、そのタグの最初の回から「最後の回の12時間前」までに公開された記事を対象にし、観測が10回以上あるタグだけを出す。

- 新着に出た回で人気にも出た本数（same_update）
- 公開から人気に初めて出るまでの時間（中央値）

注意：1日2回の観測では、短い時間だけ人気に出た記事を見落とす。

## 更新の時刻

1時間おきに見ていた期間について、前の回から新着の上位10本の顔ぶれが変わったかを、後の回の時刻（時台）ごとに数える。前の回との間が1.5時間を超える組は使わない。

## 資格者（/20）

タグ探しの回だけ。人気の上位20本のうち、カードの紹介文に 医師・Dr.・ドクター・看護師・薬剤師・管理栄養士・保健師・診断士・税理士・会計士・社労士・弁護士・行政書士・司法書士 のどれかがある本数。

記事の材料に載せた数字。10/21 05:41〜10/24 00:51 の定時観測37回から出したもの。`py -m observatory check` で今の計算と照らし合わせる。

## 観測が空いたところ

- 10/22 21:47〜10/23 21:52（約24時間）
- 10/24 18:51 からは1日2回（6:51と18:51ごろ）

## カテゴリページの棚（2026-11-01 追加）

カテゴリページ（note.com/topic/…）には、キーワードごとのまとまり（棚）が5つほど並ぶ。その棚に載っている記事を data/raw/shelves の CSV にためる（kind=shelf）。

- 棚の記事：カテゴリの、いちばん新しい回に棚に出ていた記事の本数。同じ記事が2つの棚に出ていても1本と数える。noteの案内カード（書き手 info）は数えない
- スキ中央値・いちばん少ない：棚の記事のスキ
- 10スキ未満%：棚の記事のうち、スキが10未満の割合
- 24時間以内%：カードの「◯分前・◯時間前・◯日前」から出した公開時刻が、回の時刻の24時間以内の割合。1日を超えると日単位なので、24〜47時間は「1日前」とまとめて出る
- 前回から残った%：同じカテゴリの1つ前の回にも棚に出ていた記事の割合
- 新しい言葉・外れた言葉：1つ前の回と比べて、増えた棚・なくなった棚のキーワード

注意：棚の記事のスキは、見た時刻で大きく変わる。11/1 のビジネスは、10:05 に中央値9、16:53 に中央値21（棚の顔ぶれはほぼ同じで、記事のスキが伸びた）。カテゴリ同士を比べるときは、同じ時刻に見た回どうしで比べる。

## 記事の分類（2026-11-01 追加）

記事ページの分類（パンくず：大カテ＞小カテ）とハッシュタグを data/raw/articles の CSV にためる（article_meta テーブル）。ダッシュボードの「自分の記事は、どこまで届いたか」で、② カテゴリに使う。メンバー版に出すのは自分の記事の分類だけ。

## カテゴリの棚の数字（共有アプリ、2026-11-02 追加）

build.py の `_shelf_stats`。カテゴリの1回分の棚から出す。同じ記事が2つの棚に出ていても1本と数える。

- 棚のスキの位置（少ないほうから4分の1・中央値・多いほうから4分の1）：棚の記事のスキを並べたときの位置（`metrics._q`、近い順位の値をそのまま使う）
- 24時間以内の記事：カードの「◯時間前」が24未満の記事。「1日前」は24時間として数えるので、入らない
- 24時間以内の記事のスキ（中央値・いちばん少ない）と、公開からの時間（中央値）：「最初の何時間で何スキあれば棚に入っているか」の目安
- スキの集まる速さ：24時間以内の記事の「スキ ÷ 公開からの時間（1時間未満は1時間）」の中央値。24時間以内の記事が3本未満なら出さない
- 前の回から残った記事：どちらの回にも記事番号があれば URL で、片方にでもなければ書き手で照らし合わせる（`metrics.kept_urls`）。11/1 10:03 の一巡は記事番号を取っていないので、その回との比べは書き手で照らし合わせている
- 公開した時台（24時間以内の記事）と、公開からの時間（0〜23時間・24時間以上）の本数

11/1 10:03 の一巡（49カテゴリ）は、ブラウザに残っていた記録から CSV にした（data/raw/shelves/note_棚_raw_2026-11-01_1003.csv）。記事番号がないので、URL の欄は「/書き手/x/（書き手とタイトルから作った印）」。この回の記事は、記事の照合表（アプリの「記事を調べる」）には入らない。

## 狙い目の点数（共有アプリ、2026-11-02 追加）

比べる相手の中で「下から何%の位置か」（`metrics.pct_rank`、同じ値は真ん中の位置）を、良い向きにそろえて平均する（`metrics.add_scores`）。0〜100で、50がちょうど真ん中。値のない項目は飛ばして残りで平均し、総合点は点数のある軸だけの重みつき平均。順位は、比べる相手のうち自分より点数が高いものの数＋1。

### カテゴリ（build.py の CATEGORY_AXES・CATEGORY_WEIGHTS）

比べるのは「一巡の回」（見たことのあるカテゴリの8割以上を見た、いちばん新しい回）の数字どうし。棚のスキは見た時刻で大きく変わるため。

2026-11-06 から、棚は1回10カテゴリずつ巡回して見る（月・火・木・金・土の16:40。5回で一巡）。一巡の回が8日より古くなったら、直近8日の巡回で、カテゴリごとのいちばん新しい回どうしを比べる（`build.ROLL_DAYS`）。見る時刻はどの回も16:40にそろえ、時刻による差を小さくしている。それでも見た日は最大で約1週間ずれるので、アプリでは「11/7〜11/13の巡回」のように期間を出す。直近8日にカテゴリの8割以上がそろわないときは、古い一巡の回のまま比べる。

| 軸 | 項目（向き） |
|---|---|
| 入口の低さ | 棚のスキ（少ないほうから4分の1）が少ない／10スキ未満の割合が高い |
| 入れかわり | 24時間以内の記事の割合が高い／棚の記事の古さ（中央値）が短い |
| 読者の厚み | 棚のスキ（多いほうから4分の1）が多い／スキの集まる速さが速い |
| 狙い目 | 入口の低さ×0.4 ＋ 入れかわり×0.3 ＋ 読者の厚み×0.3 |

- 比べる相手から外すもの（点数は出す。順位は「その位置に入るなら」の参考）：同じ棚を出している小カテゴリ（同じ回で、記事のスキ・古さと言葉が全部同じもの。例：スポーツと野球、創作系と小説）の2つ目、棚の記事が15本より少ないカテゴリ、一巡の回に見ていないカテゴリ
- 突出：比べる相手の中央値から、中央値からのずれの中央値（MAD×1.4826）で測って2.5倍以上離れた値（`metrics.robust_z`）。スキ・速さ・古さは log(1+x) で比べる
- 印：10スキ未満が50%以上「入口が低い」、24時間以内が70%以上「毎日入れかわる」、20%以下「古い記事が残る」、有料が15%以上「有料も並ぶ」
- 出しやすい時間帯：一巡の回とその後の回の、24時間以内の記事の公開した時台を足して、記事がいちばん多い連続3時間

### 棚の言葉（WORD_AXES・WORD_WEIGHTS）

同じ回の言葉どうしで比べる。記事が3本以上の棚だけを比べる相手にする。

| 軸 | 項目（向き） |
|---|---|
| 入りやすさ | 棚の記事のスキ（中央値）が少ない／24時間以内の記事の割合が高い |
| 伸びしろ | 棚でいちばん多いスキが多い |
| 狙い目 | 入りやすさ×0.7 ＋ 伸びしろ×0.3 |

### タグ（TAG_AXES・TAG_WEIGHTS）

タグごとの数字（定時観測とタグ探しの行を両方）を全部で比べる。タグ探しは10/25の1回だけで、ハッシュタグのページから新着に切り替えて数えたので、測り方が違う。

| 軸 | 項目（向き） |
|---|---|
| 入口の低さ | 人気の上位20本のいちばん少ないスキが少ない／少ないほうから4分の1のスキが少ない（どちらも最近6回の中央値） |
| 入れかわり | 人気の上位20本の古さが短い |
| 競争の薄さ | 1日の新着（目安）が少ない／資格者が少ない（タグ探しだけ） |
| 読者の厚み | 人気1位のスキが多い（最近6回の中央値） |
| 狙い目 | 入口×0.35 ＋ 入れかわり×0.25 ＋ 競争の薄さ×0.2 ＋ 読者×0.2 |

### 記事が出る時刻と、棚に並ぶ時刻

- 記事が出る時刻（`_supply_hours`）：新着の40本目が20時間以上前のタグ（1日の新着が少ないタグ）だけで、新着に出た記事の公開した時台を数える。新着の多いタグは、観測した時刻の直前の記事しか見えず、時刻が偏るため
- 棚での多さ ÷ 出ている記事の多さ：5カテゴリ以上を見た回ごとに、24時間以内の棚の記事の公開した時台の割合を、記事が出る時刻の割合で割る。1より大きいほど、その時台に出た記事が棚に多い。出ている記事が2%未満の時台は出さない（数本の違いで大きく振れるため）

これらの点数は、観測の範囲での目安。点数が高い所に出せば棚に載る、という約束ではない。

## 一次情報の点（10項目、2026-11-07〜）

1項目1点、10点満点。定義は config/scoring.json。前半5項目（体験・条件・自分の数字・選択・失敗）は 2026-10-27〜31 の本文採点（80本、0〜5点）と同じで、そのときの平均は、タグの人気に入った記事 3.8点・入らなかった記事 2.1点。後半5項目は 誰に・なぜ・どうやって・出どころ・新しさ。

- 採点するのは、ログアウトで読める無料部分だけ。判定は人か Claude（定時タスク）。`metrics.score_text` は本文の合図の数を出すだけで、点数ではない。
- 「出どころ」は、外から持ってきた数字や主張に名前と日付かリンクが付いているか。外の情報を使っていない記事は1。真偽は確かめられない（確かめられる形になっているか、だけ）。
- 「新しさ」は、本文の出来事・数字が公開の時点で3か月以内か。公開日が分からないときは今日から数える。
- 週の採点（木曜）：#note副業 の人気の上位20本と、約7日前の人気の一覧になかった記事3本まで（`build.pick_candidates`）。一度採点した記事は読み直さず、前の点を使う。
- 書き方の加点（最大4点）：7W1H（8つが本文で分かる）・書き出し（タイトルの問いに3文以内で答える）・独自性（自分で作った表・比べ・名前付け・自分のデータ）・読みやすさ（見出し／図表／1文の短さ／箇条書きのうち2つ）。紹介するかは基本点で決め、加点は並び順と「今週の一本」に使う。
- 紹介記事に名前を出すのは基本5点以上だけ。点数は書き手の良し悪しではなく、読者が確かめられる形と読める形になっているかの数。物差しの名前は「一次情報スコア」。
